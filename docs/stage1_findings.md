## 3. Timestamp Structure

- **Nominal sampling:** 1 Hz (per documentation)
- **Observed dominant gap:** 10 seconds (88.2% of consecutive pairs)
- **9s gap:** 8.5% (minor jitter)
- **Index:** integer, increments by exactly 10 per row → consistent with 10s storage
- **Gaps > 60s:** 331 occurrences (some multi-hour gaps — likely maintenance windows or system restarts)
- **Conclusion:** Data is effectively a ~**10-second time series**, not 1-second. The 1Hz label appears to refer to the original acquisition rate; the stored CSV contains every 10th sample.

## 6. Sensor Signatures at Failure (measured from data)

During confirmed failure windows, the following patterns are consistently observed vs pre-failure baseline:

| Sensor | Pre-failure (normal) | During failure | Signal |
|--------|---------------------|----------------|--------|
| `H1` | ~7–8 bar | **~0 bar** | ⬇️ drops sharply |
| `TP2` | ~0.6–2 bar | **~8–9 bar** | ⬆️ high — compressor pressurised |
| `DV_pressure` | ~0 (near zero) | **~1.9–2.0 bar** | ⬆️ elevated |
| `Oil_temperature` | ~55–70°C | **~74–84°C** | ⬆️ elevated |
| `Motor_current` | ~1.2–3 A | **~5.5 A** | ⬆️ elevated (under-load state) |
| `DV_eletric` | ~8–25% active | **~97–100%** | ⬆️ compressor locked under load |
| `COMP` | ~75–89% active | **~0–3%** | ⬇️ intake valve inactive |
| `MPG` | ~75–89% active | **~0–3%** | ⬇️ matches COMP |
| `LPS` | 0–1.3% active | **0–32.7%** (F4 only) | ⚠️ pressure drops below 7 bar in severe event |

**Interpretation:** Air leak forces the compressor to run continuously under load to maintain pressure. The load state is clearly distinguishable from normal cycling behaviour.

## 7. LPS Signal (Low Pressure Switch) Analysis

- **127 LPS=1 events** across the full dataset
- First occurrence: 2020-02-06 (weeks before first reported failure)
- Events span the entire dataset; not exclusive to failure windows
- Most LPS events are **very short** (9–300s); a few are very long (F2 gap: 2898 min, F4 pre: several hours)
- **Conclusion:** LPS=1 is a **weak anomaly signal** — it fires frequently as normal operational transients, but significantly elevated LPS duration/frequency correlates with degradation leading to F3 and F4

## 8. Predictive Target Validity Assessment

### Can we build a scientifically valid predictive model?

**Yes — with important caveats:**

| Aspect | Assessment |
|--------|-----------|
| **Label quality** | 4 externally-validated failure events with start/end timestamps — credible but very few |
| **Class imbalance** | Failure windows = ~29,000 rows / 1,516,948 total ≈ **~2% of data** — severe imbalance |
| **Failure homogeneity** | All 4 failures are the same type (air leak) — no multi-class scenario |
| **Pre-failure signal** | Clear sensor divergence is observable in failure windows; pre-failure drift is detectable in some cases (F4 shows elevated LPS in the 3 days prior) |
| **Temporal leakage risk** | **High** — standard cross-validation would leak future data into training. Must use time-ordered splits (train on first N months, test on last M months) |
| **Very few labeled failures** | 4 events is insufficient for supervised learning alone — **anomaly detection is the primary model; supervised is secondary/validation only** |
| **Unlabeled anomalies** | Many LPS events, Oil_level=0 periods, and Caudal_impulses=0 periods exist outside the 4 documented failures — unclear if these are true failures or normal operational states |

### Recommended modeling strategy

1. **Primary: Unsupervised anomaly detection** (Isolation Forest, Autoencoder) trained on clean "normal" pre-failure data
2. **Secondary: Semi-supervised binary classifier** trained with the 4 failure windows as positive labels and carefully windowed negative labels, using temporal CV
3. **Tertiary: RUL regression** on the two longer pre-failure windows (F3, F4) where degradation is observable

## 9. Feature Engineering Opportunities

| Feature type | Examples |
|-------------|---------|
| Rolling statistics | 30-min rolling mean/std/max of TP2, H1, Oil_temp, Motor_current |
| Cycle-based features | Compressor on/off cycles per hour; mean cycle duration |
| Pressure differential | TP3 − TP2 (leakage proxy), TP3 − Reservoirs |
| Motor state encoding | Discrete state from Motor_current (off/offloaded/loaded/starting) |
| Load fraction | % time DV_eletric=1 per rolling window |
| LPS event rate | Count of LPS activations per hour in rolling window |
| Time-of-day / day-of-week | Operational schedule effects |
| Inter-failure RUL | Time since last maintenance event |

## 10. Risks Summary

| Risk | Severity | Mitigation |
|------|----------|-----------|
| Temporal data leakage | 🔴 High | Strict time-ordered train/test splits; no shuffling |
| Class imbalance (2% failure) | 🔴 High | SMOTE on feature level (not raw time series); use precision-recall AUC not accuracy |
| Only 4 labeled failures | 🟠 Medium | Anomaly detection as primary; treat supervised results as indicative only |
| Unlabeled anomalies in "normal" data | 🟠 Medium | Use conservative "clean" training window (Feb–Mar only for normal baseline) |
| Timestamp gaps | 🟡 Low | Fill or flag during resampling; do not interpolate long gaps |
| Float precision noise | 🟡 Low | Round to 4dp during preprocessing |
